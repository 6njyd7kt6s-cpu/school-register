# 校园记录

面向值班老师的手机竖屏学生违规登记网站。

## 功能

- 老师账号和密码登录；管理员开通、停用账号。
- 从学生名册选择年段、班级、姓名和学号。
- 手机现场拍照，压缩后上传；保存时自动记录北京时间。
- 自然周（周一至周日）、自然月统计，各班次数及各年段最高班级，支持并列。
- CSV 导出，可用 Excel 打开；打印或保存 PDF。
- 同一登记重试不重复计数。学生学号唯一；重复导入已有名单自动跳过。

## 免费部署：静态网站 + Supabase

1. 在 Supabase 创建独立免费项目。
2. 执行 `supabase/migrations/001_school.sql`。该脚本新建学校数据表和私有照片桶，不用于已有健身项目。
3. 部署 `supabase/functions/school-api/index.ts`，函数名 `school-api`，关闭网关旧式 JWT 验证；函数内通过 `auth.getUser()` 核验每个请求的真实登录身份，并检查老师是否启用及管理员权限。
4. 在 Supabase Auth 中关闭公开注册。创建首个管理员用户，登录标识如 `admin@school.invalid`。通过 Auth 控制台设置密码并确认用户；在 teachers 表增加同一用户 ID、username 为 admin、姓名、role 为 admin。
5. 编辑 `public/config.js`，只填写项目公开 URL 和 publishable key。绝不能填写 service role 或 secret key。
6. `npm ci`，然后 `npm run build:web`。将 `web-dist` 发布到静态托管。也可启用仓库的 Pages 工作流。
7. 管理员登录，批量导入名单，再给老师开通账号。

所有业务表启用 RLS 并撤销匿名和登录用户直接读写权限；数据访问统一经过受身份和角色检查保护的函数。照片桶私有，查看时返回 60 秒临时地址。密码由 Supabase Auth 管理，前端不保存密码。

免费服务有容量与可用性限制，请从学校网络验证访问效果。无需 ChatGPT 或 GitHub 账号登录业务网站。

## 独立服务器部署（备用）

要求 Node.js 24。运行 `npm run build:web` 后，设置 `NODE_ENV=production`、`PUBLIC_ORIGIN=https://你的域名`、`DATA_DIR` 为持久目录，启动 `npm run serve`。通过 HTTPS 反向代理访问。首次启动会在服务器日志显示一次性初始化链接，由管理员自行设置首个账号和密码。

数据库及照片保存在 DATA_DIR，必须将其挂载到持久磁盘。该模式不适用于无持久磁盘的免费容器。备份整个数据目录时停止服务，确保数据库与照片一致。

## 名册导入

Excel 中复制四列，不含表头：年段、班级、学号、姓名。每行一名学生，使用制表符或英文逗号分隔。支持初一、初二、初三、高一、高二、高三。每次最多3000人。

## 隐私

仓库不包含真实学生名单、成绩、照片、数据库、密码或服务密钥。测试名单与测试记录均不进入公开网页资源。班级统计按登记次数计数，不是违规人数。
